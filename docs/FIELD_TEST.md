# iPhone 16 Pro 与两台相机验收

## 手机 RAW 验收（优先）

使用侧载包，记录系统、App 版本、提交 SHA 和 IPA SHA256。稳定光线下先拍灰卡，再拍有人物、高光和暗部的静止场景。

- 相机准备诊断应为后置物理主摄、1×、Bayer RAW；如果不可用，记录具体提示，不能记为通过，也不能用 ProRAW 替代。
- 每次拍摄 ID 不同。导出当前 DNG，文件能被支持 DNG 的工具打开，确认传统 Bayer CFA 信息；该步骤用于验证，不影响 App 内拍摄、不需购买摄影软件。
- 结果诊断的光圈、快门、ISO、朝向和格式应与**同一个导出 DNG**元数据相符。拍摄时间、RAW 和 JPEG 确认属于同次请求。
- 重要区域高光应与真实高光位置对应；人物框、点选区域、屏幕方向和导出图匹配。用角落亮斑检查旋转坐标，不能只用居中灰卡。
- 灰卡／阶梯亮度检查黑白电平归一化；如果显示“高光检查未完成”，记录 DNG 黑电平、白电平、重复模式和 RAW 格式码，保持此项未通过。
- 拒绝相机权限、锁屏／后台中断、恢复前台、连拍、拍摄失败、断网、15 秒超时、迟到响应分别检查；旧结果不能覆盖新拍摄。
- 新拍摄或清除当前结果后，旧临时 RAW 应删除；历史仍含参数／预览，不含 RAW。导出的副本不会自动删除。
- 浅色／深色、大字体、VoiceOver、降低透明度、减少动态效果逐项检查，特别是取景主按钮、两张参数卡和折叠解释。
- 只有主动保存预览才出现图库权限；联网关闭时监测不应发送图像。开启时检查所发送 JPEG ≤1280px，无 GPS/EXIF。

## 灰卡校准

按 App 向导对每台相机的实际焦距分别三次拍摄。稳定持续光，灰卡方向、位置和光线相同；相机手动曝光、关闭自动 ISO／闪光。记录认可曝光来源。不同场景光线再测试同一版本，记录偏差，不要为了让统计通过而回填参考值。

## 学校新闻三场景

每台相机分别拍会议课堂、颁奖交接和多排合影。先核对 App 推荐的光圈、快门、ISO 在实物上均可设置。固定相机曝光步长为 1/3，200D 静态 ISO 整档；记下镜头实际焦距及显示最大光圈。

建议首轮各机各场景至少十个稳定光线样本。每个样本记录认可参考曝光和起始参数；同一主体、取景和持续光下比较，不能把不同灯光的测量混为同一次。

曝光差按 `log2(N推荐²/t推荐) − log2(ISO推荐/100) − [log2(N参考²/t参考) − log2(ISO参考/100)]` 计算，正值表示推荐偏暗。对稳定光线样本按机身统计绝对值 ≤2/3 EV 的比例；90% 是项目目标，不是当前保证。

人物清晰度必须按学校实际刊发像素／印刷尺寸看样片。将运动模糊、景深不足、失焦、灯光问题分开记录：“人物模糊”会加快快门，“景深不足”会提高必要光圈约束；失焦需要检查 AF 和对焦对象，灯光条纹需要另行试拍排查。

合影记录最近／最远人物距离、排间距和实际对焦位置；无距离预设先检查前后排。颁奖检查交接动作和手势。会议课堂检查讲话、翻页和手持抖动。闪光样本单独记录，不纳入持续光曝光算法验收。

完成后将统计结果、系统版本和对应提交写入 VALIDATION.md；公开仓库只记录匿名数据／统计，实际新闻照片留在本机。
